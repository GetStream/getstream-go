# getstream-go

Official Go server SDK for Stream Chat, Video, Feeds, and Moderation.

- Default branch: `main`
- Module: `github.com/GetStream/getstream-go/v7`
- Package: `getstream`
- Clone sibling of the chat monorepo as `../chat` (required for OpenAPI regen)

## Layout

Generated (header `Code generated by GetStream internal OpenAPI code generator. DO NOT EDIT.`): `call.go`, `channel.go`, `chat.go`, `common.go`, `feeds.go`, `feeds-v3.go`, `models.go`, `moderation.go`, `requests.go`, `rfc3339.go`, `video.go`, `webhook.go`, plus matching `*_test.go` and `moderation_integration_test.go` that the generator emits.

Handwritten: `client.go`, `http.go`, `retry.go`, `logging.go`, `logger.go`, `errors.go`, `stream.go`, `tasks.go`, `rate_limits.go`, `version.go`, and the remaining `*_test.go` files.

- Webhook fixtures: `tests/fixtures/webhooks/`
- Extra test helper: `feedtest/`
- Spec pin after regen: `.spec-version`

Do not hand-edit generated files. Change the generator in chat (`chat-manager openapi generate-client --language go-serverside`) and re-run `./generate.sh`.

## Local commands

```bash
cp .env.example .env   # STREAM_API_KEY, STREAM_API_SECRET, STREAM_BASE_URL
make build
make fmt
make lint              # ./lint.sh
make test-unit         # go test -short -v ./...
make test              # go test -v ./...
make test-integration  # go test -coverprofile cover.out -v -race -parallel 16 -timeout 20m ./...
make generate          # ./generate.sh
make setup-hooks       # git config core.hooksPath .githooks
```

Tests load `STREAM_API_KEY`, `STREAM_API_SECRET`, `STREAM_BASE_URL`. `CONTRIBUTING.md` also mentions `STREAM_KEY` / `STREAM_SECRET`; the code and CI use the `STREAM_API_*` names. Optional: `STREAM_MULTI_TENANT_KEY` / `STREAM_MULTI_TENANT_SECRET` (skipped if unset).

## OpenAPI regen

`./generate.sh` (or `make generate`):

1. Resolves the latest GitHub release tag on `GetStream/protocol` whose name starts with `openapi-`.
2. Downloads `openapi/v2/serverside-api.yaml` from that tag.
3. Builds `chat-manager` from `../chat` (`make -C projects/chat-manager build`) and runs `openapi generate-client --language go-serverside` plus `generate-webhook-fixtures` into this repo.
4. Writes `.spec-version` (protocol spec tag + chat generator revision) and runs `./lint.sh`.

Requires `jq` and a local `../chat` checkout. Generator tooling is internal (Stream developers only).

Additive API surface from regen is a **minor** (`feat:`), not a major. Do not bump the Go module major (`/vN` in `go.mod`) unless there is a real breaking change; see `CONTRIBUTING.md` major-version steps.

## CI

Workflows in `.github/workflows/`:

| File | Name | Trigger |
|---|---|---|
| `ci.yml` | build | push/PR to `main` |
| `lint.yml` | Lint | pull_request |
| `pr_title.yml` | Lint PR title | pull_request (conventional title required) |
| `reviewdog.yml` | reviewdog | pull_request (golangci-lint via reviewdog) |
| `release.yml` | Release | push to `main` or `*.x`, plus `workflow_dispatch` |
| `scheduled_test.yml` | Scheduled tests | Monday 09:00 UTC + `workflow_dispatch` |

`ci.yml` job `test-build` uses GitHub environment `feeds-enabled-shard`, Go matrix `1.19`–`1.24`. Go 1.19 runs full integration tests; other versions run `go test -short`.

Vars (names only): `STREAM_BASE_URL`, `STREAM_API_KEY`.
Secrets (names only): `STREAM_API_SECRET`, `CODECOV_TOKEN`, `SLACK_NOTIFICATIONS_BOT_TOKEN`.

Known flakes: live Chat API 503 when the CI app sits on a bad shard; `scheduled_test.yml` retries the suite 3 times. Integration tests need the `feeds-enabled-shard` environment credentials.

## Release

release-please (`release-please-config.json`, `.release-please-manifest.json`). Extra file: `version.go`.

1. Merge PRs to `main` with **conventional-commit PR titles**. The squash subject is what release-please uses. Only `feat`, `fix`, `perf`, and breaking changes produce a release.
2. Review the Release PR opened by `github-actions[bot]`. Approve and run held checks; if it is behind `main`, click **Update branch**.
3. Merge the Release PR. That creates the Git tag (e.g. `v7.1.0`) and GitHub Release. `proxy.golang.org` / pkg.go.dev pick up the tag. There is no Maven/PyPI-style publish job.

Force a version with a `Release-As: X.Y.Z` footer on the squash commit (not only in the PR description). Hotfixes: `*.x` maintenance branches; see `CONTRIBUTING.md`.

Majors: land `feat!`, migrate `go.mod` and self-imports to `/vN` in a **separate** PR, then merge the major Release PR. Never merge a major Release PR before the `go.mod` path matches. Details in `CONTRIBUTING.md`.

## PR conventions

- Sign the Stream CLA (`PULL_REQUEST_TEMPLATE.md`).
- Conventional PR title (`pr_title.yml`). Example regen: `feat: regenerate from OpenAPI` (minor).
- Changelog is generated from those titles (`CHANGELOG.md`).
